# pi-background-bash

独立的 Pi 扩展：让模型把 Bash 命令放到后台，完成后自动唤醒当前会话。

仅使用 Pi 的公开 API 和 Node 内置模块，没有额外运行时依赖。执行、shell 配置、会话环境、前台输出格式、进程树终止都复用 Pi 原生 Bash 后端；不修改 Pi Web、模型 provider、认证、提示词处理或全局设置。

## 安装

现与 `pi-error-retry` 在[统一仓库](../README.md)管理。本地开发目录：`~/pi-dev/pi-extensions-shuyuan/pi-background-bash`。

从 GitHub 一次安装两个扩展：

```bash
pi install git:github.com/librola/pi-extensions-shuyuan
```

从 npm 仅安装本扩展：

```bash
pi install npm:@librola33/pi-background-bash
```

注意：npm 包名为 **`@librola33/pi-background-bash`**；无作用域的 `pi-background-bash` 是其他维护者的项目，不要混用。目录名、工具与命令名、事件协议和 Web 界面 ID 仍为原来的名称。

也可安装本地子目录：

```bash
# 加入全局 Pi 包列表；此命令会修改 ~/.pi/agent/settings.json
pi install ~/pi-dev/pi-extensions-shuyuan/pi-background-bash
```

随后在 Pi 中执行 `/reload`，或新开会话。Pi Web 也从同一份 Pi 包配置加载扩展；正在运行的会话需 reload 或重新打开。

只在一次 CLI 启动中试用，不改全局设置：

```bash
pi -e ~/pi-dev/pi-extensions-shuyuan/pi-background-bash/src/index.ts
```

不要与原来的独立包重复加载，也不要同时加载其他替换 `bash` 执行逻辑的扩展；替换工具不能自动组合。`!` / `!!` 用户 shell 命令保持 Pi 原生行为，本扩展只接管模型调用的 `bash`。

## 原生任务 widget（CLI 与原版 Pi Web）

原生扩展使用 `ctx.ui.setWidget()` 提供任务信息，不创建额外的点击入口或弹层，不接管宿主 footer。当且仅当当前会话存在正在运行的后台任务时显示；最后一个后台任务结束或停止后立即隐藏，即使还有前台任务或历史记录。没有运行中的后台任务时，`/bash-jobs` 和快捷键也不会强制显示 widget。

- CLI：输入框下方默认只显示摘要。`Ctrl+Shift+J` 原位展开/收起同一个 widget，`/bash-jobs` 原位展开；组合键需要终端支持其编码，不识别时使用命令。之前单行鼠标点击打开弹层的入口已移除。
- CLI 展开时：方向键、Page Up/Down、Home/End 查看列表；Esc 只收起，不移动编辑器焦点，也不停止主 agent 或后台任务。其他弹层拥有输入焦点时不会拦截它的按键。
- RPC / 原版 Pi Web：widget 提供完整的运行中后台任务列表，由原版 Pi Web 自带的底栏按钮负责折叠和展开；不依赖终端鼠标回调、CLI 快捷键或 `custom()` 弹层。`/bash-jobs` 也通过 widget 提供信息，不再只是文本通知。
- 列表只包含 `background && status === "running"` 的任务，不显示前台任务或已结束任务；显示任务 ID、耗时和命令预览，命令预览最多 200 个终端显示列。耗时按整秒显示为 `1h 2m 3s`，省略为零的单位，不满一秒显示 `<1s`。设置了 `hard_timeout` 时另显示 `hard limit 2h` 等配置总时限，保留小数秒；这是整个命令的执行上限，不是后台剩余倒计时，移交不会重置。未设置则不显示硬时限。
- 查看不调用模型、不插入会话消息，也不自动读取日志或停止任务；只有后台任务运行时每秒更新耗时，最后一个后台任务结束后移除 widget 并释放计时器。会话关闭、树导航、替换或 reload 同样释放 widget、输入监听和计时器。

显示过滤不删除任务数据：`bash_jobs` 仍可查询前台任务及最近 20 个终态记录，完成通知和唤醒逻辑不变。

CLI 使用宿主提供的 `pi-tui >=1.5.2 <2`，不打包另一套 TUI 或增加运行时依赖。扩展版 Pi Web 的既有浏览器入口、顶部下拉框和桥接协议独立保留，本次原生兼容不改动它们。

## Web 端（扩展版 Pi Web API v1）

同一个包同时声明 `pi.extensions` 和 `piWeb`。CLI 只加载原生入口；你在 `/data/repos/pi-web/hkk/pi-web-ext` 中提供的 Web 扩展宿主加载浏览器入口和受限桥接，不需要修改或重新构建 Pi Web。

1. 用上面的 npm 或本地路径安装命令登记为持久 Pi 包，CLI 与 Web 服务使用同一个 agent 目录。Web 桥的目标包身份为 `@librola33/pi-background-bash`，公开事件频道不变。
2. 如果原生实例尚不支持 `0.2.x` 公共协议，先停止需要保留的活动任务，再执行原生 `/reload`；原生 reload 会清理本插件的活动任务。`0.2.1` 的顶部计数兼容已加载的 `0.2.0` 实例，只更新 Web 资源即可，无须重启正在运行的任务。
3. Web 端重新聚焦、使用 Web Reload 或刷新页面，发现新版 `piWeb` 资源。Web Reload 不替代原生 reload，也不会重启任务引擎。

### 顶部下拉框

- 入口放在顶部 **工具** 后面的 **后台任务 1 ▾**，不注册侧栏面板、不打开右侧标签、不挤占聊天宽度。
- 无需展开即可看到当前会话正在执行的后台任务数量，每 2 秒自动只读更新。只统计 `background && running`，不包含前台命令或已完成任务；已确认没有后台任务时显示 0，未运行/未加载兼容实例或查询失败时不显示数字，不把历史 `running` 当作当前数量。切换会话不会复用上个会话的数量。
- 点击展开；点击外部、收起按钮或 Esc 关闭。Esc 被下拉框消费，不会误触主 agent 的停止快捷键。
- 展开时只读会话历史，并每 2 秒轻量同步已保存的完成记录。历史中的 `running` 只显示“当前状态未确认”，不会假装跨重启恢复了进程。
- **刷新任务** 查询已加载原生实例的真实状态；点击任务读取当前输出。Web 输出最多末尾 200 行 / 16 KiB，完整日志路径仍可供原生 `read` 读取。
- **开启实时刷新** 后，才每 2 秒查询详细进程状态和当前输出；关闭下拉框时清理详情轮询，顶部数量继续更新。隐藏页面时不发请求，恢复可见立即刷新数量，禁用 Web 时释放全部轮询。
- **停止任务**、**转入后台** 都先确认，再操作当前会话已有的任务。视图失效不意味着操作被撤销，不会自动重试写操作。
- 浏览器中的 `/bash-jobs` 展开同一个下拉框，不发模型提示。原生 CLI 的 `/bash-jobs` 仍显示任务列表。
- 自有格式的工具结果和完成消息有专用卡片，只展示任务信息和原始内容，不添加打开下拉框的重复按钮；任务管理统一从顶部入口或 Web `/bash-jobs` 打开，不接管其他插件的同名工具。

查询不启动 AgentSession、不调用模型、不写上下文。没有活动或兼容的原生实例时，界面仅展示历史并提示原生 reload；缺失目标不会回落为模型提示。关闭或仅禁用 Web 展示不会停止原生任务。

浏览器使用宿主 React 和主题变量，所有资源为预构建原生 ESM。下拉框使用浏览器顶层 popover，旧 Safari 回退为原生 dialog，避开移动工具栏的裁剪；输出只按文本展示，不执行 HTML。CLI `-e` 临时加载不是持久包声明，不会触发自动 Web 发现。

### 公共桥接协议

原生扩展在当前会话事件总线上提供 `pi-background-bash:rpc:v1:request`，按请求 ID 回到 `pi-background-bash:rpc:v1:reply:<requestId>`。版本 1 的方法为 `ping`、`list`、`status`、`output`、`stop`、`background`；不接受任意 shell 命令、文件路径或其他会话的任务。

Web 桥动作均要求 `session: active`；查询只能用前四个方法，写操作单独声明。顶部 `count` 动作复用原生 `list`，只返回 `{ running: N }`，不增加原生方法、不启动实例、不向浏览器发送完整任务列表或日志。每次操作都先校验原生实例报告的版本、会话身份、格式和能力，兼容范围为 `>=0.2.0 <0.3.0`。后台工具和完成记录附带 `pi-background-bash.job.v1` 格式标识供安全匹配。后端桥是独立单文件，不在浏览器资产白名单中，也不导入或重写执行引擎。

## 模型调用

```js
// 短命令直接返回；未配置时默认等待 180 秒（3 分钟），未完成则移交后台，不重新启动命令。
bash({ command: "npm test" })

// 立即后台执行。
bash({ command: "npm test", background: true })

// 等待 5 秒后转后台；包括后台运行在内，最多执行 10 分钟。
bash({ command: "npm test", timeout: 5, hard_timeout: 600 })
```

`timeout` 是 **TUI/RPC 的前台等待期限**，不是强制终止期限。`hard_timeout` 才会终止进程树，默认不设置。

默认开启自动转后台，等待为 **180 秒（3 分钟）**，可在全局 `~/.pi/agent/settings.json` 或项目 `.pi/settings.json` 中添加（单位为秒）：

```json
{
  "backgroundBash": {
    "defaultTimeoutSeconds": 180,
    "autoBackground": true
  }
}
```

优先级：**单次调用的 `timeout` > Pi 有效设置中的配置值（项目覆盖全局，遵循项目信任规则）> 180 秒**。配置必须是合法的正数秒数；非法默认配置会拒绝需要使用它的命令，不静默回落。`background: true` 不等待，显式 `timeout` 不依赖默认配置；print/JSON 模式不使用此软等待默认值。

`autoBackground` 默认为 `true`，必须使用 JSON 布尔值。设为 `false` 后，命令继续前台等待，不创建自动移交计时器；即使设置了软 `timeout` 也不自动后台、不因软等待期限终止。显式 `background: true`、`/bash-bg` 和快捷键仍可手动移交，`hard_timeout` 仍然生效。开关不影响已经运行的命令。

插件只读取设置，不自动修改配置文件。修改文件后按宿主的设置重载机制生效，或新开会话；原生 `/reload` 会清理活动任务，勿在需要保留任务时执行。配置变更只影响随后启动的命令，不重设已运行任务的期限。

文本返回明确区分主动后台、前台等待超时转后台和手动移交。等待超时会写明配置的秒数，例如 `Foreground wait timed out after 180s. The command was not terminated; it was moved to the background.`，随后保留任务 ID、真实状态、日志路径和完成通知说明；自动移交后仍在运行时，额外给出带实际任务 ID 的 `bash_jobs({ action: "stop", id: "job-..." })` 停止方法，并说明停止主 agent 不会停止后台任务。主动后台、手动移交或已经终止的任务不追加这段提示；不会把软等待超时表述成命令被终止。

后台返回包含：

```json
{
  "status": "running",
  "job_id": "job-0123abcd",
  "output": "当前输出摘要",
  "truncated": false,
  "full_output_path": "/tmp/pi-background-bash-xxxxxx/job-0123abcd.log",
  "wall_time_seconds": 0
}
```

运行中的任务 **没有 `exit_code`**；不会用 0 或 124 伪造执行结果。普通前台完成保留 Pi 原生的 `structuredContent` 和非零退出错误标记，codemode 可以使用同样的字段。

### 可选的状态和输出查询

```js
bash_jobs({ action: "list" })
bash_jobs({ action: "status", id: "job-0123abcd" })
bash_jobs({ action: "output", id: "job-0123abcd", tail: 100 })
bash_jobs({ action: "stop", id: "job-0123abcd" })
```

- `list`：当前会话的运行中任务及最近 20 个完成任务；命令预览最多 200 字符。
- `status`：立即返回状态、真实退出码（如果存在）、起止时间、日志大小和路径，不等待任务完成。
- `output`：立即返回已经产生的输出，默认末尾 200 行，最多 2000 行 / 32 KiB，并给出完整日志路径。
- `stop`：用 Pi 原生的进程树终止方式停止任务；Linux/macOS 使用 SIGKILL，不承诺优雅退出。

状态包括 `running`、`completed`、`failed`、`stopped`、`timed_out`、`output_limit`。只有后端报告实际退出码时才提供 `exit_code`。

查询是可选的点时检查，不是等待机制。任务完成后，扩展发送一次 `pi-background-bash:completion` 自定义消息，带任务 ID、状态、退出码、耗时、日志路径及末尾 20 行 / 4 KiB 摘要：

- 模型空闲时：先保存可见完成记录，再用隐藏的唤醒提示启动后续一轮，避免重复展示。
- 模型正在工作时：完成记录以 `triggerTurn: false` 交给 SDK，在当前工具调用和结果都落盘后的安全 `turn_end` 写入历史。后续请求已包含这条完成记录、且模型正常响应后，取消该任务的待唤醒，不再额外开启一轮。仍未确认已读的结果等自然 `agent_settled` 再唤醒；不会打断其他工具，也不依赖可被清除的 follow-up 队列保存事实。
- 主运行被 Stop / Esc 中止时：保留完成记录，取消待唤醒；任务若在 Stop 后才完成，也只保存结果，不重新启动模型。下一次正常运行后恢复自动唤醒，旧待唤醒不会补发。
- 同一轮内仅为仍未确认已读的任务合并唤醒一次，列表最多保存最近 20 个任务 ID；完成记录本身不会因此截尾。超过列表上限另保留一个布尔标记，保守补一次唤醒，避免较早任务未读、最近任务已读时漏掉结果；这也可能在截尾结果实际已读时多唤醒一次。若只有截尾标记需要唤醒，提示不列任务 ID。`pi-background-bash:wakeup` 设置 `display: false`，只负责触发后续一轮，不展示重复提示；只引用已保存的结果，不重复记录完成事实。完成通知仍保持 `display: true`，具体展示和折叠由宿主决定。
- 没有其他工作时：模型结束当前回复，等待通知；不需要反复 `sleep`、轮询状态或读取日志。

“已读”按公开 `context_with_system` 中本扩展的完成消息快照，以及该次 assistant 的正常 `message_end`（stop/toolUse/length）确认，不猜测模型是否口头处理过结果。仅准备上下文、收到流式 start、失败或 pending/deferred 占位响应不算已读；请求进行中才完成的任务不属于已有快照。这个观察点在所有 `context` 变换之后，但后续 `context_with_system` 或 provider payload 重写仍可改变输入；后续变换应保留完成消息，SDK 的这些公开事件无法证明任意后置重写后的最终输入。

忙碌时可见记录要到安全边界才能写入，不承诺进程崩溃前一定落盘。`0.2.2` 修复了 Stop 清队丢通知和 Stop 后意外唤醒的边界；已被旧版本丢弃的历史消息不会自动重写或补发。

扩展不伪造用户输入。输出和通知中的日志必须作为命令数据处理，不能当作新的指令。

### 手动移交

- `/bash-bg [任务ID]`：把指定或最近启动的前台命令移交后台。
- `Ctrl+Shift+B`：移交最近启动的前台命令（CLI 终端需支持此按键编码）。
- `/bash-jobs`：显示任务列表。

命令移交后台后会解除与原工具调用 AbortSignal 的关联，因此之后按 Esc 不会误杀已经移交的后台任务；停止后台任务请使用 `bash_jobs action=stop`。

## 生命周期和边界

- 任务属于当前会话实例；其他会话不能凭 ID 查询或停止它。
- 关闭会话、reload、新建/切换会话或树导航时，终止原实例的活动任务，禁止旧任务通知进入新上下文。
- 第一版**不跨进程重启恢复任务，也不跨 reload 保留活动任务**。旧日志仅在回收前可按原路径读取，不会恢复到新实例的任务列表。直接使用 SDK 的宿主应先分发 `session_shutdown` 再 `dispose()`；单独 `dispose()` 不是本扩展的清理通知。
- 日志位于系统临时目录，权限 0600；每个命令最多写入 64 MiB，超过后立即终止。完整日志按下面的上下文与七天规则回收，不是永久保存的附件。
- 每个会话最多同时运行 16 个命令。任务、命令前缀和环境使用当前宿主配置；不会把 `shellCommandPrefix` 的内容暴露到任务通知，也不把 `PI_WEB_PASSWORD` 传给子进程。
- 不要用 `nohup`、`setsid` 或末尾 `&` 手工脱离进程树；直接使用 `background: true`。主动守护进程化的后代不在可靠追踪范围，宿主崩溃或被 SIGKILL 也不承诺清理。
- print / JSON 是短生命周期模式，无法保证完成后唤醒：拒绝显式 `background: true`，关闭自动移交；此时 `timeout` 保留原生硬超时语义，`hard_timeout` 优先。
- 如运行于 Pi Web，扩展可选注册其现有 session-liveness 协议，在有活动任务时避免自动闲置回收。显式关闭或替换会话仍优先；普通 Pi 不依赖该协议。

## 日志回收

回收范围仅限本扩展创建的临时任务日志，包含前台与后台命令；**不删除或改写 Pi 会话 JSONL、聊天消息、摘要或分支**。

- 运行中任务永不按年龄回收；写入者消失但只留下 `running` 标记时仍按未知保留，不能把 PID 消失伪装为完成。
- 会话超过七天没有真实活动时，其日志可过期，但运行任务、在途正常请求和其他七天活动窗口内会话的引用仍保护日志。真实输入、模型回合与工具操作记活动，widget 刷新、Web 轮询、读取与清理扫描不续命。
- 未过期会话中，未读结果从结果生成起保留七天；超过七天只解除未读保护，**不覆盖有效上下文的引用保护**。已读且不再被有效上下文引用的终态日志可回收。
- 回收的已读账本独立于唤醒队列和最近二十条任务列表。结果身份和原文指纹必须在请求快照中匹配，并在公开 `before_provider_request` 观察到原文，随后收到正常 assistant 响应（stop/toolUse/length）；仅构建上下文、Stop、错误、改写了正文的同 ID 结果和后台 handoff 不算已读。嵌套 codemode 结果或传输封装无法提供此证据时保守视为未读。
- 引用按公开 `buildSessionProjection()` 的有效保留区、压缩/分支摘要、系统提示、工具参数及结果正文检查，不扫描展示用 `details` 作为模型引用。目录、相对路径或 `$TMPDIR` 等无法安全求值的引用保守保护整个同名目录；压缩、树切换或上下文编辑后，旧的无引用证明失效，正常请求确认后再清理。

每个实例日志目录只增加一份权限 0600 的原子写入索引，持久保存会话归属、实际活动、已读和日志版本，不给每个日志另建元数据文件。会话实例仍不恢复旧进程。回收在正常回合结束、压缩、关闭与加载实例的每小时检查中执行；不启动独立守护进程，因此到期不保证立即删除。旧分支或历史消息中的 `full_output_path` 之后可能失效，任务状态和已保存的输出摘要保持不变；`bash_jobs output` 区分本实例已回收与文件无故缺失。

没有索引的旧目录不猜测归属或已读：七天内保留；七天后仅在有效上下文扫描完整、文件版本未变且能完整检查本用户写入进程的 fd 时回收。旧目录的 fd 检查目前仅支持 Linux，其他平台或权限不足时保留。索引/会话损坏、文件替换、活动写入者不明和扫描超预算都保守跳过；发现同一临时根仍有外部进程的活跃索引时延后回收，避免把跨进程扫描误当原子锁；同进程的实例共用增量缓存并避免并发读入大历史库。当前扫描上限为一万个会话、单会话 256 MiB、每次未缓存输入 2 GiB、单索引 8 MiB。公开 hook 不是任意后置扩展/传输重写的最终审计接口，依赖这些重写的宿主应保留结果原文；插件不会改写宿主私有管线来制造“已读”证明。
